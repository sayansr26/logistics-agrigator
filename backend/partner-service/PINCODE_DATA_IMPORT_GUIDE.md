# Pincode Data Import Guide

## Overview

This guide explains the complete pincode data processing and import pipeline for the Partner Service.

## Data Pipeline Architecture

```
IN.txt (11MB raw TSV)
    ↓
[Python merge script]
    ↓
merged_pincode_data.csv
    ↓
[Node.js import script]
    ↓
PostgreSQL Database
```

## Directory Structure

```
backend/partner-service/
├── pincode-api/                    # Complete pincode processing system
│   ├── IN.txt                      # Raw GeoNames data (19,300+ pincodes)
│   ├── merge_pincode_data.py      # Python script to generate CSV
│   ├── digipin.js                  # Pincode encoding utilities
│   ├── index.js                    # Express API server (optional)
│   ├── pincode_lookup.py          # Python lookup utilities
│   ├── package.json                # Dependencies for pincode-api
│   └── requirements.txt            # Python dependencies
│
├── scripts/
│   ├── load-pincode-data.js       # Step 1: Run Python merge script
│   └── import-pincode-data.js     # Step 2: Import CSV to database
│
└── data/
    └── merged_pincode_data.csv    # Generated by load script
```

## Step-by-Step Import Process

### Step 1: Load Pincode Data (Generate CSV)

This step processes the raw IN.txt file and generates merged_pincode_data.csv:

```bash
# From project root
cd backend/partner-service
pnpm run load:pincodes
```

**What it does:**

1. Reads `pincode-api/IN.txt` (11MB TSV file with lat/lng data)
2. Optionally merges with `All_India_Pincode_directory.csv` (if available)
3. Generates `data/merged_pincode_data.csv` with columns:
   - pincode: 6-digit code
   - area: Area/locality name
   - lat: Latitude (decimal)
   - lng: Longitude (decimal)
   - district: District name
   - state: State name
   - type: urban/rural/unknown

### Step 2: Import to Database

This step imports the CSV data into PostgreSQL:

```bash
# From project root
cd backend/partner-service
pnpm run import:pincodes
```

**What it does:**

1. Reads `data/merged_pincode_data.csv`
2. Creates geographical hierarchy:
   - States (findOrCreateState)
   - Cities/Districts (findOrCreateCity)
   - Areas (findOrCreateArea)
   - Pincodes (bulk insert)
3. Processes in batches of 1000 records
4. Uses caching to avoid duplicate queries
5. Skips duplicates automatically
6. Creates audit logs

## Database Schema

### Models Involved

```prisma
model State {
  id        String   @id @default(uuid()) @db.Uuid
  name      String   @db.VarChar(255)
  code      String   @db.VarChar(50)
  status    Boolean  @default(true)
  cities    City[]
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@map("states")
}

model City {
  id        String   @id @default(uuid()) @db.Uuid
  name      String   @db.VarChar(255)
  stateId   String   @db.Uuid
  code      String?  @db.VarChar(50)
  status    Boolean  @default(true)
  state     State    @relation(fields: [stateId], references: [id])
  areas     Area[]
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@map("cities")
}

model Area {
  id        String    @id @default(uuid()) @db.Uuid
  name      String    @db.VarChar(255)
  cityId    String    @db.Uuid
  status    Boolean   @default(true)
  city      City      @relation(fields: [cityId], references: [id])
  pincodes  Pincode[]
  createdAt DateTime  @default(now())
  updatedAt DateTime  @updatedAt

  @@map("areas")
}

model Pincode {
  id        String   @id @default(uuid()) @db.Uuid
  areaId    String   @db.Uuid
  code      String   @db.VarChar(6)
  district  String?  @db.VarChar(255)
  latitude  Float?
  longitude Float?
  type      String?  @db.VarChar(50)
  status    Boolean  @default(true)
  area      Area     @relation(fields: [areaId], references: [id])
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@unique([code])
  @@map("pincodes")
}
```

## Troubleshooting

### Issue: Python script fails

**Solution 1: Python not installed**

```bash
# macOS
brew install python3

# Ubuntu/Debian
sudo apt-get install python3

# Verify
python3 --version
```

**Solution 2: pandas missing**

```bash
pip install pandas
# or
pip3 install pandas
```

### Issue: CSV file not found

**Solution:**

```bash
# Ensure load script ran successfully
ls -lh backend/partner-service/data/merged_pincode_data.csv

# If missing, run load script again
cd backend/partner-service
pnpm run load:pincodes
```

### Issue: Import fails with Prisma errors

**Solution 1: Regenerate Prisma client**

```bash
cd backend/partner-service
pnpm run generate
```

**Solution 2: Check database connection**

```bash
docker-compose ps
# Ensure postgres container is running

docker logs logistics-postgres
# Check for connection issues
```

### Issue: Duplicate key errors during import

**Solution:**
The import script uses `skipDuplicates: true`, so duplicates are automatically handled. If you need to re-import:

```bash
# Option 1: Reset database
cd backend/partner-service
pnpm run db:reset

# Option 2: Manually delete pincode data
docker exec -it logistics-postgres psql -U partner_admin -d partner_service -c "
TRUNCATE pincodes, areas, cities, states CASCADE;
"
```

## Performance Considerations

### Import Speed

- **Batch Size**: 1000 records per batch
- **Caching**: States, cities, and areas are cached to avoid duplicate queries
- **Expected Time**: ~2-3 minutes for 19,300 pincodes
- **Processing Speed**: ~125 records/second

### Optimization Tips

1. **Increase batch size** for faster imports (edit BATCH_SIZE in import script)
2. **Disable indexes** temporarily during import (advanced)
3. **Use direct DB connection** instead of Prisma for bulk operations (advanced)

## Data Sources

### IN.txt (GeoNames)

- **Source**: http://download.geonames.org/export/zip/
- **Format**: Tab-separated values (TSV)
- **Columns**: country_code, pincode, area, state, state_code, district, etc.
- **Size**: 11MB (19,300+ records for India)

### All_India_Pincode_directory.csv (India Post)

- **Source**: India Post official data
- **Format**: Comma-separated values (CSV)
- **Additional Data**: Office names, office types (B.O, H.O, S.O), delivery status
- **Purpose**: Enriches GeoNames data with official India Post information
